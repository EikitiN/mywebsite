サイト全体や少なくとも備忘録にはキーワード検索機能を付けたいが、このウェブサイトのコンセプトとして、あまり外部ツールを使わないということを掲げている。 では、AIに聞いてみよう。便利なものを使うことに違和感はないが、それを完成品としてしまうのは少しもったいない。 AIに聞くと、やはり自前でやるなら対応表を作るしかない、と。もう少し詳しく要望を伝えながら、実装にこぎつけよう。

メモ

基本的な方針は、html文書中の連続する文字列の長さとその出現回数、出現位置に応じてスコアを割り振り、それらの合計で内容との適合度を測ることであろう。 そもそも、ものを書く人間は、変な論説文とかではなければ、タイトルとか、概要に重要な情報をまとめるだろう。 タイトル、メタタグのsummary, tagsは必要なキーワードが入っている確率が高い。 ではそのまま実装した時のことを考えよう。きっと「を」がほとんどのページで最も重要な情報になってしまうだろう。 助詞は除外しないと。 ストップワードでは取得すべき内容ごと破損する可能製。少し調べるとページ間で出現割合が高いものを独自性のないワードとして除外することもできるらしい。 また、2-gramという手法があるらしい。各文字を2文字ずつにスライスし、それと検索キーワード間で一致性を確かめるらしい。実装してみる

生成側: 全文統一で2-gram 区切り(半角スペースや句読点など)をまたぐ2-gramは生成しない。区切り位置を示すために、"\uE000\uE000"を用いる。 一文字だけの場合、\uE000でパディング(例: 「あ」→"あ": "\u3042\uE000") スコアリング: ページ単位でsetを用いて、用いられた2-gramを出す。 全ページでそれらを足し、何%の割合のページに出現するかを算出する→p


0<p<=0.5: [IDEscore] = -3.6p^2 + 1
0.5<p<=1: [IDEscore] = -0.3p + 0.1
各2gramのスコア = [文字別スコア]*[位置スコア]*[IDEスコア]

ページ内では、ひらがな、ひらがなの組み合わせに対して0.9、ひらがな、その他の組み合わせに対して0.4、その他、その他の組み合わせに対して1.1、\uE000、\uE000の組み合わせに対して0.0のスコアを振る。
